支付方式示例值错误 已修复
测试发现传 "微信支付" 报错 paymentMethod 值无效。
原因：Swagger 示例写的是中文，但后端只接受英文码。
已修正所有接口的示例值为正确格式。
paymentMethod 可选值： property_coin — 物业币 point — 积分 wechat — 微信 mixed — 混合支付 注意：必须传英文码，不能传中文
11
预约服务混合支付已实现 已修复
测试发现物业币支付报错 paymentMethod 值无效，同时混合支付功能缺失。
已实现混合支付：支持积分+物业币+微信组合付款。
微信部分传0或不传即可跳过，测试时只用积分+物业币就能跑通。
预约服务混合支付： POST /services/{id}/book { "paymentMethod": "mixed", "pointUsed": 5000, // 使用积分数 "coinUsed": 30, // 使用物业币数 "address": "阳光花园1栋101", "contactPhone": "13800138000" } 计算逻辑： 积分部分 = pointUsed × 兑换比例（默认0.01） 物业币部分 = coinUsed × 1元 微信部分 = 总金额 - 积分部分 - 物业币部分 微信部分为0时自动跳过，无需对接微信支付

退出家庭： POST /families/me/leave Header: Authorization: Bearer {token} 响应示例： { "memberId": "res_xxx", "familyId": "fam_xxx", "pointsHandling": "TRANSFER", "coinsHandling": "TRANSFER" } 限制：户主不可退出，需先转让户主或解散家庭

禁用用户显示为"已冻结" 前端
测试发现被禁用的用户在积分管理界面显示"已冻结"，解冻后账号恢复正常。

外卖分类点击后显示商家但无商品 前端
测试点击"外卖"分类后，商家显示了但商品列表为空。

筛选商家分类： GET /merchants?category=外卖 PRD定义6类：外卖 / 周围商家 / 自营 / 农家 / 外卖小吃 / 团购 获取商家下的商品（不能用category筛选）： GET /products?merchantId=mch_demo001
7
商家联盟分类筛选看不到商品 前端
系统采用两级分类：商家有商家分类（外卖等），商品有子类目（饮料等）。
筛选商品时必须用商家ID，不能用商家分类去筛商品。
获取某个商家的商品： GET /products?merchantId=mch_demo001 错误做法： GET /products?category=外卖 ← 这样筛不到，因为商品category是"饮料""面食"等 正确流程： 1. 先按商家分类筛商家列表：GET /merchants?category=外卖 2. 点击某个商家 3. 再调用 GET /products?merchantId=xxx 获取该商家的所有商品
