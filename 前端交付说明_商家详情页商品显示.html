商家详情页商品显示问题 — 修复说明与接口字段交付

交付对象：前端 · 版本：2026-10-02 · 对应后端分支 2026-10-02 · 接口文档同步至 v8.8

一、问题结论（先看这里）

排查确认：后端商品对象的 name、price 字段一直存在且命名正确，不是"字段名写错"导致的问题。真正的原因是下面两点：

根因说明
文档缺失 商家详情页取错了来源 商家详情页的商品其实由 GET /merchants/{id} 内联返回（字段 products[]），但旧文档 §7.3 完全没有写这个字段，前端不知道有它，所以商品区渲染不出内容。
调用报错 独立商品接口的必要参数 GET /products?merchantId=xxx 在未登录且未传 propertyCompanyId 时会直接返回 10001 参数缺失（HTTP 400）。旧文档把该参数标为"可选"且示例不带，前端照文档调用必然失败。本次已修复：传了 merchantId 时后端会自动从商家推导物业公司。
取值陷阱 字段会"整个消失" 全局 Jackson 配置为 default-property-inclusion=non_null，值为 null 的字段不会出现在 JSON 里（不是返回 null）。最典型的是 memberPrice（业主价）只在登录时返回。

二、商家详情页：商品直接从这里取 推荐

2.1 接口

GET /api/v1/merchants/{id}
Auth: Optional（可选登录）
Roles: any

商家详情页渲染商品列表，直接用这个接口返回的 data.products 即可，无需再调 GET /products。

2.2 取数规则

  • 只包含该商家 status = "active" 且未被软删除的商品；
  • 按 createdAt 倒序，最多返回 20 条；
  • 商家没有上架商品时，products 为空数组 []（不会缺失该字段）。

2.3 响应示例

{
  "code": 0,
  "message": "success",
  "data": {
    "id": "mch_demo001",
    "name": "万达超市",
    "status": "active",
    "products": [
      {
        "id": "prd_demo001",
        "name": "可口可乐330ml",
        "description": "经典碳酸饮料",
        "coverUrl": "https://cdn.example.com/product/prd_demo001.jpg",
        "price": 3.50,
        "memberPrice": 3.00,
        "pointPrice": 350,
        "stock": 100,
        "category": "饮料",
        "status": "active"
      }
    ]
  },
  "timestamp": "2026-07-01 15:23:33"
}

2.4 products[] 字段表

字段类型必返说明
idString是商品ID（prd_ 前缀）
nameString是商品名称
priceNumber是原价（元）
memberPriceNumber否业主价。仅携带登录态时返回，未登录时字段不出现
pointPriceInteger否积分兑换价，可为空
stockInteger是库存
categoryString否商品分类，可为空
statusString是active / inactive / sold_out
coverUrlString否封面图，可为空
descriptionString否商品描述，可为空

三、商品列表接口（独立调用时）

GET /api/v1/products?page=1&pageSize=20&merchantId=mch_xxx
Auth: Optional
Roles: any

3.1 propertyCompanyId 的取值规则（本次变更）行为变更

调用方是否传 propertyCompanyId结果
平台管理员跨物业查询时必传按传入值过滤
已登录用户（居民/商家/技师/物业管理员）不传自动取当前用户所属物业公司（跨物业隔离）
未登录不传，但传了 merchantId自动从该商家推导物业公司，可正常返回该店商品 本次修复
未登录不传，也没传 merchantId返回 10001 参数缺失（HTTP 400）
给前端的建议：做"某个商家的商品列表"时，优先用 GET /merchants/{id} 的 products（一次请求拿商家信息+商品）；若确实要分页/筛选商品，再用 GET /products 并务必带上 merchantId。

3.2 响应字段（data.list[]）

字段类型必返说明
idString是商品ID
merchantIdString是所属商家ID
merchantNameString否所属商家名称
nameString是商品名称
priceNumber是原价（元）
memberPriceNumber否业主价，仅登录时返回
pointPriceInteger否积分兑换价
stockInteger是库存
categoryString否分类
statusString是商品状态
coverUrlString否封面图
descriptionString否描述
createdAtString是创建时间（ISO UTC）

四、必须注意的取值陷阱

不要这样写：
if (item.memberPrice === null) ... —— 字段可能根本不存在，item.memberPrice 是 undefined。
请这样写：
const mp = item.memberPrice ?? item.price; // 无业主价时回退原价
或 if (item.memberPrice != null) { /* 显示业主价 */ }
  • 所有可空字段（memberPrice、pointPrice、category、coverUrl、description）在为空时字段不出现，请统一做空值兜底。
  • 不要依赖字段一定存在来判断接口是否成功——请以 code === 0 判断。

五、排查对照表

现象原因处理
商家详情页商品区空白没读 data.products改用 GET /merchants/{id} 的 products 渲染
商品列表接口 400 / code=10001未登录又没传 propertyCompanyId（也没传 merchantId）带上 merchantId（已修复）或显式传 propertyCompanyId
商品列表返回空数组跨物业隔离：商家不属于当前用户物业公司属预期行为；或改用商家详情接口
业主价不显示未登录 → memberPrice 字段不返回登录后重试，或按上面的空值兜底处理
