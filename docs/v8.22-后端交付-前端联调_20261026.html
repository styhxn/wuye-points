02商家页汇总字段 新增返回

GET /merchants/my 顶层新增三个字段，前端不用再自己数订单或误读余额。

字段类型口径
totalOrdersnumber累计订单数，不含已取消/已退款
pointBalancenumber商家购分账户剩余积分（与 /merchant/points/* 同一账户）
profitBalancenumber盈利余额，与 withdrawableAmount 同口径
 
{
  "code": 0,
  "data": {
    "id": "mch_xxx",
    "withdrawableAmount": 1280.50,
    "totalOrders": 128,
    "pointBalance": 5000,
    "profitBalance": 1280.50
  }
}
注意：coinBalance 仍是「商家绑定居民的物业币余额」，不要当积分余额使用。

03广告：免费额度永久一次 + 微信现金 规则变更

支付方式只保留 free 与 wechat；免费额度不再按周重置。

3.1 支付方式

paymentMethod状态说明
free可用每个商家永久仅一次
wechat可用返回 payParams，受服务端开关控制
coin / point / mock已下线返回 400：广告已不支持物业币、商家积分或模拟支付

3.2 报价与额度

GET /merchant/ads/quote?days=7 的 freeQuotaRemaining 改为“永久是否还有一次”：历史用过即 0。freeQuotaPerWeek 仅保留为配置值，请勿再用于“本周额度”判断。

3.3 微信下单

POST /merchant/ads 或 /targeted 传 paymentMethod=wechat 时，广告先落 pending_payment，响应带支付参数：

{
  "code": 0,
  "data": {
    "id": "mad_xxx",
    "status": "pending_payment",
    "payStatus": "unpaid",
    "paymentRecordId": "pay_xxx",
    "payParams": {
      "timeStamp": "1730000000",
      "nonceStr": "abc123",
      "package": "prepay_id=wx123",
      "signType": "RSA",
      "paySign": "xxxx"
    }
  }
}
前端务必：只有拿到 payParams 才调 wx.requestPayment；没有 payParams 不能当作免费成功。支付回调成功后才开始投放。

3.4 列表状态

GET /merchant/ads 每项新增 payStatus（unpaid/paid/refunded）与 paymentRecordId，可在列表标注“待支付”。

04代理货源订单归属 新增接口

业主小店卖一级代理商的货：订单、发货、结算、售后面向一级代理商；业主小店只拿佣金。

履约入口：代销订单的 merchantId 写一级代理商，residentMerchantId 写业主小店。一级代理商可直接用既有 POST /merchants/my/orders/{orderId}/fulfillment 发货；业主小店不再出现在自己的订单销售列表，佣金在卖货明细里查看。

4.1 订单新增字段

字段值含义
sourceTypemall / distributor代销订单为 distributor
distributorId商家ID一级代理商（结算主体）
residentMerchantId商家ID业主小店店铺主体
settlementOwnerdistributor结算归属方

4.3 业主小店卖货明细

GET /resident-merchants/settlements 每项新增 commissionAmount（佣金，等于 resellerProfit）、distributorMerchantId、sourceType=distributor、settlementOwner=distributor。

小店端展示“到账金额”请用 commissionAmount，不要用 orderAmount（那是买家成交额）。

05楼长统一收益账户 口径变更

字段名不变，数值改为账号级合并口径，提现也从统一账户校验。

字段新口径
totalEarning楼长分成 + 业主卖货收益 + 名下商家剩余可提现
withdrawnAmount账号下全部角色已完成提现
pendingAmount账号下全部角色在途提现
withdrawableAmount统一可提现（已扣除微信分账已到账部分）
商家提现、业主卖货提现也加了统一账户兜底，避免同一住户用不同角色重复提同一笔钱。

06会话楼长标识 新增字段

GET /messages/conversations 每项新增 isBuildingLeader；GET /messages/neighbors 新增 isBuildingLeader / isUnitLeader，并把楼长、单元负责人排在最前。

{ "peerId": "res_xxx", "peerName": "李四", "isBuildingLeader": true }

07推荐商家排序 范围扩大

GET /merchants/official-recommended 与 GET /merchants?recommended=true 继续返回 isRecommended、recommendedSort，顺序为 recommendedSort → rankOrder → levelWeight 降序。

v8.22 起，被物业推荐的业主小店/代销小店也会出现在推荐结果中（此前会被常规列表过滤）。

08奖励金转钱包 新增接口

POST /property-coins/transfer-to-wallet，只从个人奖励金转出，不动家庭池。

请求

{ "coinAmount": 100.00 }

响应

{
  "recordId": "coin_xxx",
  "coinBalance": 40.00,
  "walletBalance": 100.00
}

规则：生成 source=transfer_to_wallet 的 spend 流水 + 钱包入账流水；不可撤销；余额不足返回 COIN_INSUFFICIENT。

09积分规则收敛 行为变更

积分只有一种用途：转物业公司，抵扣物业费；积分在消费/交易中产生。

9.1 转物业费

POST /residents/me/points/transfer-to-property

  • 物业公司总开关 point_transfer_enabled 默认关闭，关闭时返回 400；
  • 开启后还需入住满 point_transfer_min_years（默认 5 年）；
  • 按账期由早到晚冲抵 unpaid/partial/overdue 账单，并回写账单状态；
  • 响应新增 appliedFeeAmount（实际冲抵金额）。
{
  "code": 0,
  "data": {
    "recordId": "pt_xxx",
    "pointAmount": 100,
    "balanceAfter": 400,
    "appliedFeeAmount": 1.00,
    "transferredAt": "2026-10-26T10:00:00Z"
  }
}

9.2 需要前端下线的入口

入口后端行为
POST /points/transfer 家庭内转赠400：积分仅可用于抵扣物业费，暂不支持家庭内转赠
商城下单 pointUsed > 0400：积分仅可用于抵扣物业费，商城下单不支持积分抵扣
请移除商城结算页的“积分抵扣”勾选，pointUsed 固定传 0 或不传；否则试算/下单会被后端拦下。

10视频增量后端项

新增 quarterlyFee、perTimeFee；订阅 subType 支持 monthly/quarterly/yearly/per_time。

联系店主带商品 新增入参

POST /messages、/messages/neighbor-chat 可传 relatedProductId 或 relatedListingId。

商品流带店铺 新增字段
