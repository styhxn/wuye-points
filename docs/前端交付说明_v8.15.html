1. 问题1 · 一级代理审核通过返回 400已修复

1.1 前端反馈现象

POST /api/v1/admin/distributor-applications/dap_37dcd56a341000/audit
Body: { "auditStatus": "approved" }
→ HTTP 400
{ "code": 50000, "message": "数据保存失败（数据库约束冲突）:
  Column 'is_canteen_main_merchant' cannot be null" }

1.2 根因

  • merchants 表的 is_canteen_main_merchant（以及 merchant_type、serve_all_communities、is_distributor）是 NOT NULL DEFAULT 列。
  • 审核通过时后端新建商家载体，JPA 会把实体中未赋值的字段显式写成 NULL；数据库的 DEFAULT 只在该列不出现在 INSERT 语句时才生效，因此约束报错。
  • 一级代理审核与活动组长审核通过都会建店，所以两处同时受影响。

1.3 修复内容（后端）

  • 实体层为四个 NOT NULL 字段补默认值：merchant_type='goods'、is_canteen_main_merchant=false、serve_all_communities=true、is_distributor=false，并标注 nullable=false。
  • 该修复覆盖后端全部 8 处建店路径（一级代理、组长、技工、业主小店、物业经理、管理端建商家、食堂等），不是只修审核这一处。
  • 一级代理审核仍保持原副作用：同事务创建 platform_merchants + merchants（is_distributor=1、merchant_source=distributor）+ merchant_property_configs。

2. 问题2 · 活动组组长申请/审核全链路已闭环

C端提交申请→ C端查进度→ 管理端列表→ 审核通过 / 驳回→ 组长身份 + 组长小店→ （可选）撤销身份

2.1 接口清单

C 端（住户）

方法 & 路径角色说明
POST /activity-leader-applications/applyresident提交申请。请求 activityField≤50（可选）、remark≤200（可选）
GET /activity-leader-applications/my-applicationresident查询本人最新申请：none/pending/approved/rejected

管理端（物业 / 平台）

方法 & 路径角色说明

2.2 状态机

状态含义前端表现
none从未申请申请页展示表单
pending待审核展示「审核中」，禁用重复提交
approved已通过刷新 /auth/profile，isActivityLeader=true，进入组长管理页
rejected已驳回展示 rejectReason，允许修改后重新申请

2.3 审核通过会发生什么

  • 创建（或复用）activity_leader_identities 的 active 身份记录，申请记录写入 activityLeaderIdentityId。
  • 自动开通组长小店：merchants.merchant_source=group_leader、merchant_type=group_leader、audit_status=approved、status=active，并创建 merchant_property_configs。
  • 住户 role 始终是 resident，组长只是叠加标签；论坛、家庭、业主小店、一级代理等能力不受影响。
  • GET /auth/profile / GET /residents/me 的 isActivityLeader 变为 true，activityLeaderId 返回身份ID。
  • 审核通过不会自动创建活动组：组长进入组长管理页后，通过现有 POST /activity-groups 创建活动组并自动成为该组组长。
前端禁止用 JWT 的 role==activity_leader 判断组长。组长账号的 role 恒为 resident，必须使用 profile 的 isActivityLeader 标签做入口显隐与路由。审核通过后也不需要再调用任何「开通小店」接口，开店已在审核事务内完成。

2.5 幂等与重试

  • 同一住户同物业已有 pending 申请，或已是 active 组长：再次提交返回 97062。
  • 申请已被审核（非 pending）：再次审核返回 97061。
  • 审核通过时若该住户已有 active 组长身份，会复用身份，不重复创建；小店开通按手机号 + 来源幂等复用。
  • 本次修复前审核失败的申请仍为 pending，新版本部署后直接重试即可。

3. 其它一并修复的问题已修复

3.1 「我的申请」恒返回 none

涉及接口：

  • GET /distributors/my/application（一级代理）
  • GET /individual-leaders/my-application（个体负责人）

原因：服务层把 null 作为审核状态传入派生查询，被翻译成 audit_status IS NULL，因此永远查不到记录。现改为按 createdAt 倒序返回本人最新一条申请，调用方式与响应字段均不变。

3.2 平台超管跨物业列表为空

GET /admin/distributor-applications、GET /admin/activity-leader-applications 在 platform_admin 不传 propertyCompanyId 时，原实现会追加 property_company_id = NULL 条件导致查不到数据。现改为「有值才过滤」，不传即返回全部物业；property_admin 仍强制本物业，不受影响。

4. 前端改造 / 联调清单重点

4.1 一级代理管理端

  • 无需改接口。审核弹窗保持不变；部署后对 pending 申请重新点击「通过」验证成功。
  • 成功响应中的 distributorMerchantId 可用于跳转商家详情或展示开通结果。
  • 驳回时确保 rejectReason 非空，否则返回 PARAM_MISSING。

4.2 活动组组长 C 端

  • 「我的」页「活动组组长」入口：isActivityLeader=true → 组长管理页；false → 申请页。
  • 申请页进入时调用 GET /activity-leader-applications/my-application：pending 展示审核中并禁用提交；rejected 展示原因并允许重新提交；none 展示表单。
  • 提交成功后本地置为 pending；若用户从管理端得知已通过，重新拉取 /auth/profile 刷新标签。

4.3 活动组组长管理端

  • 新增/完善「组长申请」列表页：状态 Tab（待审核 / 已通过 / 已驳回），分页参数 page/pageSize。
  • 审核弹窗：通过仅传 auditStatus=approved；驳回必须填写 rejectReason（≤200 字）。
  • 通过成功后提示「已通过，并已自动开通组长小店」，可用返回的 activityLeaderIdentityId 做后续查询；不要再调用开店接口。
  • 组长详情/列表可增加「撤销组长身份」操作，二次确认后调用 POST /admin/activity-leaders/{residentId}/revoke。
  • 平台超管列表页无需强制选择物业；不传 propertyCompanyId 即查看全部。

4.4 不要再做的事

  • 不要用 role==activity_leader 判断组长身份（role 恒为 resident）。
  • 不要在审核通过后额外调用「创建店铺 / 开通小店」接口（后端已自动完成）。
  • 不要为本次修复新增任何请求字段或改造 URL。
