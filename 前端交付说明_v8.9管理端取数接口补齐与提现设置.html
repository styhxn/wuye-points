一、先看结论

  • 本次只「加接口」，不改任何既有接口的路径、出入参与返回结构。前端可增量接入，无破坏性变更。
  • 无数据库变更，无需执行迁移脚本。所用字段（withdrawal_blocked、auto_withdrawal_*、settlement_balance 等）均已在库。
  • 8 个只读接口此前调用返回 404，现已可用，用于补齐「后台管理端数据查看」页面的取数。
  • 6 个写接口此前文档已声明但从未实现，现已补齐：结算提现申请/审批/拒绝、提现设置更新、提现资格阻止/解阻止。
  • 权限口径不变：管理端接口仍走 property_admin / platform_admin，并受物业公司数据隔离约束。

三、只读接口明细

3.1 配送员与配送订单 §9.8 / §10.5.3 / §10.5.4

GET/deliveries/couriers — 可用配送员分页

角色：merchant、property_admin、platform_admin、coordinator、sector_leader、individual_leader

Query 参数类型必填说明
pageint否默认 1
pageSizeint否默认 20（上限 100）
propertyCompanyIdString否仅 platform_admin 可用以跨公司筛选；其余角色强制取本人所属物业

响应 data.list[]（CourierOptionResponse）：

字段类型说明
idString配送员住户 ID（res_ 前缀，与 courierId 相同）
courierIdString配送员住户 ID，指派时传给 §9.7 的 courierId
courierNameString姓名
statusStringonline＝有进行中配送单（accepted/picked）；offline＝空闲
createdAtString创建时间

GET/admin/couriers — 配送员列表（管理端）

角色：property_admin、platform_admin。参数与响应与 §9.8 完全同源，仅路径不同，供管理端送货页使用。

GET/admin/delivery-orders — 配送相关订单列表（管理端）

角色：property_admin、platform_admin。底层复用订单列表筛选，返回订单列表项分页（字段同 §8 订单列表 OrderListItemResponse）。

Query 参数类型必填说明
page / pageSizeint否默认 1 / 20
orderStatusString否订单状态筛选
propertyCompanyIdString否物业公司筛选（受数据隔离约束）
startDate / endDateString否时间范围
keywordString否订单号 / 商品名模糊搜索
sortString否默认 -createdAt
提示：本接口按订单维度返回（含订单金额、状态等），不额外返回配送单专属字段；若要展示配送员、配送进度，请配合 §9 配送列表接口使用。

3.2 提现审批汇总看板 §33.3 / §34.5

GET/admin/coin-withdrawals/summary — 物业币提现汇总

Query：propertyCompanyId（platform_admin 可指定，否则取当前物业）。响应（CoinWithdrawalSummaryResponse）：

字段类型说明
pendingCountLong待审笔数
pendingAmountBigDecimal待审金额合计（实到金额）
todayCompletedCountLong今日完成笔数
todayCompletedAmountBigDecimal今日完成金额合计
approvedCountLong已通过笔数（approved + completed）
approvedAmountBigDecimal已通过金额合计（实到金额）
口径说明：coin_withdrawals 表无 completed_at 字段，completed 为终态，故「今日完成」按记录的 updated_at 落在今日统计。

GET/admin/merchant-withdrawals/summary — 商家提现汇总

Query：propertyCompanyId。响应（MerchantWithdrawalSummaryResponse）：

字段类型说明
pendingCountLong待审笔数
pendingAmountBigDecimal待审金额合计（申请金额）
todayProcessedCountLong今日已审笔数（按 auditedAt）
todayProcessedAmountBigDecimal今日已审金额合计（实到金额）
approvedCountLong已通过笔数
approvedAmountBigDecimal已通过金额合计（实到金额）

四、写接口明细

4.1 物业公司结算提现 §51.11 / §51.12 / §51.13

POST/admin/property-companies/{id}/settlement-withdrawals — 提交申请

角色：property_admin、platform_admin。{id} 为物业公司 ID（pc_）。

请求体字段类型必填说明
amountBigDecimal是提现金额（元），须 > 0 且 ≤ 结算余额
curl -X POST "https://test.yuanxusoftware.top/api/v1/admin/property-companies/pc_demo001/settlement-withdrawals" \
  -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
  -d '{ "amount": 500.00 }'

行为：落库 withdrawal_records（withdrawal_type=property_company），手续费按该公司 withdrawal_fee_rate（未配置取平台默认）计算，初始状态 pending。响应：单条 RoleWithdrawalItemResponse（取其中的 id 供后续审批）。

POST.../{withdrawalId}/approve — 审批通过

角色：仅 platform_admin。无请求体。

行为：校验为 pending → 从 settlement_balance 扣减本次金额 → 状态置 approved 并写 completedAt。响应：单条 RoleWithdrawalItemResponse。

POST.../{withdrawalId}/reject — 拒绝

角色：仅 platform_admin。无请求体。

行为：校验为 pending → 状态置 rejected（不扣减余额）。响应：单条 RoleWithdrawalItemResponse。

{id}（物业公司 ID）与 {withdrawalId}（wr_）必须匹配，否则返回 403。

4.2 更新提现设置 §80.2

PUT/admin/coin-withdrawals/settings

角色：property_admin、platform_admin。Query：propertyCompanyId（platform_admin 可指定；property_admin 取当前物业，不可为空）。

请求体字段类型必填说明
autoEnabledBoolean是是否开启自动提现
periodDaysInteger是自动提现周期天数，取值 1~365
curl -X PUT "https://test.yuanxusoftware.top/api/v1/admin/coin-withdrawals/settings?propertyCompanyId=pc_demo001" \
  -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
  -d '{ "autoEnabled": true, "periodDays": 7 }'

响应：同 §80.1（返回更新后的完整设置）。写入 property_companies.auto_withdrawal_enabled / auto_withdrawal_period_days。

4.3 阻止 / 解阻止提现 §80.3 / §80.4

PUT/admin/coin-withdrawals/residents/{id}/block — 居民

角色：property_admin、platform_admin。{id} 为住户 ID（res_）。

curl -X PUT "https://test.yuanxusoftware.top/api/v1/admin/coin-withdrawals/residents/res_demo001/block" \
  -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
  -d '{ "blocked": true, "reason": "违规操作" }'

PUT/admin/coin-withdrawals/merchants/{id}/block — 商家

角色：property_admin、platform_admin。{id} 为商家 ID（mch_）。

请求体字段类型必填说明
blockedBoolean是true 阻止提现，false 解阻止
reasonString否原因，记入操作日志（不落库到业务表）

响应：data 为 null（仅以 code=0 判断成功）。

影响范围：仅写 residents.withdrawal_blocked / merchants.withdrawal_blocked， 只影响提现资格，不影响余额、消费、下单等其他功能；被阻止后自动提现任务会跳过该用户。

五、公共约定

  • 鉴权：全部需登录态，管理端接口需 property_admin 或 platform_admin；结算审批（§51.12/§51.13）仅 platform_admin。
  • 数据隔离：除 platform_admin 外，传入的 propertyCompanyId 会被强制为本人所属物业；越权访问返回 403。
  • 分页：查询参数 page（从 1 开始）、pageSize（上限 100）；响应 data.pagination。
  • 时间格式：统一返回 yyyy-MM-ddTHH:mm:ss（ISO8601，无时区后缀），前端按本地展示。
  • 金额：均为 BigDecimal（元），保留两位小数，前端避免用浮点二次计算。
  • ID 前缀：pc_ 物业公司、res_ 住户、mch_ 商家、wr_ 提现记录；传错前缀返回 10002。

六、错误码

错误码HTTP含义与场景
10001400参数缺失（如更新设置时缺 autoEnabled/periodDays，或物业 ID 未确定）
10002400参数格式错误（ID 前缀不对、auditStatus 取值非法等）
10003400参数超出范围（如 pageSize > 100）
20004403权限不足（角色不符，或访问非本人所属物业数据）
30001404住户不存在（§80.3 res_ 未找到）
60001404商家不存在（§80.4 mch_ 未找到）
60003409审核已处理（§51.12/§51.13 对非 pending 记录重复审批）
70001404提现记录不存在（withdrawalId 未找到）
94003400提现申请不允许操作（§51.11 提现额 > 结算余额；§51.12 审批时余额不足）
97001404物业公司不存在

未列出的兜底错误：99001（系统错误，HTTP 500）。建议前端优先按数字码判等，message 仅作展示。

七、联调 Checklist

  • 后台「配送管理」页：接入 /admin/couriers、/admin/delivery-orders，确认列表与分页正常。
  • 指派配送入口：接入 /deliveries/couriers，把 courierId 传给 §9.7 指派接口。
  • 提现审核看板：接入两个 /summary，展示 6 个统计字段（注意币种/金额口径区分）。
  • 物业结算页：接入 /settlement-balance + /settlement-withdrawals（列表），打通「申请 → 审批 → 拒绝」闭环。
  • 提现设置页：GET 回显 → 编辑 → PUT 保存 → 用返回体刷新页面；periodDays 前端限制 1~365。
  • 提现资格管理：blocked 开关调用对应 block 接口，成功后以 code=0 判定并提示。
  • 异常分支：重点验证 404（记录不存在）、409（重复审批）、94003（余额不足）的提示文案。
